Installation issues

Fixes for failures during bin/install.sh (e.g. package install or dpkg errors).

python3 install fails: py3clean "cannot get content of"

Symptom: Install fails with:

Exception: cannot get content of alacarte
error running python rtupdate hook alacarte
...
dpkg: error processing package python3 (--configure):
 installed python3 package post-installation script subprocess returned error exit status 4
[ERROR] Failed to install python3. Check /tmp/rpi-engineer-install-*.log for details.

Other package names that may appear include hplip-data, system-config-printer-common, thonny.

Cause: The system’s python3 package runs py3clean after install. py3clean tries to list files of other packages; if those packages are missing, half-installed, or virtual, it fails and blocks python3 configuration.

Resolution (on the Raspberry Pi or target system):

  1. Fix dpkg and try to complete configuration: 
    sudo dpkg --configure -a
sudo apt-get install -f -y
  2. If python3 still fails, remove the packages that py3clean is complaining about (only if you do not need them). Replace PACKAGE with the name from the error (e.g. alacarte, hplip-data, system-config-printer-common, thonny): 
    sudo apt remove --allow-remove-essential PACKAGE
    Repeat for each failing package, then: 
    sudo dpkg --configure -a
sudo apt-get install -f -y
  3. Confirm python3 is installed and re-run the installer: 
    python3 --version
sudo ./bin/install.sh

If you need one of those packages (e.g. printer support), install it again after the RPi Engineer install completes: sudo apt install hplip-data (or the package you removed).

WiFi hotspot: /etc/network/interfaces.d/wlan0: No such file or directory

Symptom: During "Configuring WiFi hotspot" the script fails with:

main: line 966: /etc/network/interfaces.d/wlan0: No such file or directory

Cause: On some Raspberry Pi OS setups the directory /etc/network/interfaces.d does not exist (e.g. when using NetworkManager or a minimal install).

Resolution: The installer now creates the directory automatically. If you see this with an older install script, update the repo and re-run, or create the directory and re-run: sudo mkdir -p /etc/network/interfaces.d then run the installer again.

dpkg database broken (parsing / status)

Symptom: Errors about “parsing file …/status” or “unknown characters” when running apt or the installer.

Resolution: Backup and fix /var/lib/dpkg/status (remove corrupt lines or restore from backup), then run sudo dpkg --configure -a and sudo apt-get install -f. See the installer’s pre-flight error message for exact steps.

Interrupted installation: repair / continue

Symptom: The installer was stopped partway through (power loss, Ctrl+C, or a step failed and you fixed the cause).

What the installer does: It records progress in /tmp/rpi-engineer-install.progress. If you run the installer again and that file is present, you will see:

Interrupted installation detected (progress file present).
  1) Continue / Repair (resume from where it stopped)
  2) Start over (discard progress and run a new install)

Resolution:

  • Choose 1) Continue / Repair to resume. The script reuses your previous choices (from /etc/rpi-engineer/install.conf), skips steps already completed, and continues from the next step. You will be asked for the WiFi hotspot password again if the hotspot step had not completed.
  • Choose 2) Start over to remove the progress file and run a full new installation (you will go through the wizard again).

On a successful completion, the progress file is removed automatically.
