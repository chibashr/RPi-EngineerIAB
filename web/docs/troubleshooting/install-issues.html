Installation issues

Fixes for failures during bin/install.sh (e.g. package install or dpkg errors).

python3 install fails: py3clean "cannot get content of"

Symptom: Install fails with:

Exception: cannot get content of alacarte
error running python rtupdate hook alacarte
...
dpkg: error processing package python3 (--configure):
 installed python3 package post-installation script subprocess returned error exit status 4
[ERROR] Failed to install python3. Check /tmp/rpi-engineer-install-*.log for details.

Other package names that may appear include hplip-data, system-config-printer-common, thonny.

Cause: The system’s python3 package runs py3clean after install. py3clean tries to list files of other packages; if those packages are missing, half-installed, or virtual, it fails and blocks python3 configuration.

Resolution (on the Raspberry Pi or target system):

  1. Fix dpkg and try to complete configuration: 
    sudo dpkg --configure -a
sudo apt-get install -f -y
  2. If python3 still fails, remove the packages that py3clean is complaining about (only if you do not need them). Replace PACKAGE with the name from the error (e.g. alacarte, hplip-data, system-config-printer-common, thonny): 
    sudo apt remove --allow-remove-essential PACKAGE
    Repeat for each failing package, then: 
    sudo dpkg --configure -a
sudo apt-get install -f -y
  3. Confirm python3 is installed and re-run the installer: 
    python3 --version
sudo ./bin/install.sh

If you need one of those packages (e.g. printer support), install it again after the RPi Engineer install completes: sudo apt install hplip-data (or the package you removed).

WiFi hotspot: /etc/network/interfaces.d/wlan0: No such file or directory

Symptom: During "Configuring WiFi hotspot" the script fails with:

main: line 966: /etc/network/interfaces.d/wlan0: No such file or directory

Cause: On some Raspberry Pi OS setups the directory /etc/network/interfaces.d does not exist (e.g. when using NetworkManager or a minimal install).

Resolution: The installer now creates the directory automatically. If you see this with an older install script, update the repo and re-run, or create the directory and re-run: sudo mkdir -p /etc/network/interfaces.d then run the installer again.

Install seems to hang at AnyDesk or TeamViewer

Symptom: The installer sits at "Installing AnyDesk" or "Installing TeamViewer" with no output for several minutes.

Cause: Those steps download packages and keys from the internet. On a slow connection or busy Pi this can take 5–15 minutes. The script now prints progress lines so you can see it is still working.

What to do: Wait; do not interrupt. If nothing changes for 15+ minutes, check internet and re-run (use "Continue" if offered).

dpkg database broken (parsing / status)

Symptom: Errors about “parsing file …/status” or “unknown characters” when running apt or the installer.

Resolution: Backup and fix /var/lib/dpkg/status (remove corrupt lines or restore from backup), then run sudo dpkg --configure -a and sudo apt-get install -f. See the installer’s pre-flight error message for exact steps.

Upgrade: skip configuration (use existing settings)

When you run the installer on a system that already has RPi Engineer installed, you get Upgrade mode. You can then choose:

  • Use existing configuration (only choose modules) – Keeps hostname, WiFi hotspot, and remote access settings from the previous install. You are only asked to select modules (module selection is shown on every upgrade so you can add or remove modules).
  • Re-run full configuration wizard – Runs the full wizard again (remote access, hotspot, hostname, modules, summary).

In non-interactive mode (NONINTERACTIVE=1), upgrade defaults to using existing configuration and keeping previously configured modules.

Installer fails: Deploy incomplete (missing web/index.html or similar)

Symptom: The installer exits with [ERROR] Deploy incomplete; missing: web/index.html (or services/logging_service/manager.py, bin/apply-web-permissions.sh, or paths under web/css/, web/js/).

Cause: The source directory used for deploy does not contain the required files (e.g. incomplete clone, wrong branch, or tarball without web/services/bin). On some systems the bulk copy (rsync/cp) can leave these files missing even when the source has them; the installer verifies required web assets (CSS, JS, HTML) and tries an explicit repair copy as a fallback.

Resolution: Run the installer from a complete repo clone that includes web/ (with web/css/, web/js/, web/advanced/, web/docs/), services/, and bin/. If running from /opt/rpi-engineer, the installer clones the repo automatically; ensure the device has network access and that the remote branch (e.g. main) includes these files. Otherwise clone the repo elsewhere and run ./bin/install.sh from that directory. If the error persists after a clone, ensure the files are committed and pushed to the repo you clone from.

Web interface unstyled or 404 for CSS/JS after install or upgrade

Symptom: The web UI at http://192.168.50.1 loads but with no styling (plain text, default fonts), and the browser console shows 404 (Not Found) for css/base.css, css/theme.css, js/pages/simple.js, or similar.

Cause: Required web assets under /opt/rpi-engineer/web/ were not fully copied during install or in-app update (e.g. partial deploy or rsync/copytree quirk). The box is designed for offline use: all CSS, JavaScript, and HTML are stored on the device; nothing is loaded from the internet.

Resolution:

  1. Re-run the installer (upgrade) so it can verify and repair web assets: sudo /opt/rpi-engineer/bin/install.sh, choose Upgrade and use existing configuration. The installer checks required assets (e.g. web/css/base.css, web/js/pages/simple.js) and copies web/css, web/js, web/advanced, web/docs from source if any are missing.
  2. If you applied an update from the web UI and then saw 404s, run the installer as above, or copy the full web/ tree from a complete repo: rsync -av ./web/ user@192.168.50.1:/opt/rpi-engineer/web/, then sudo /opt/rpi-engineer/bin/apply-web-permissions.sh (or restart nginx).

After a complete install or update, all UI resources are present under /opt/rpi-engineer/web/ and the interface works offline.

Service fails: can't open file .../manager.py (No such file or directory)

Symptom: journalctl -u rpi-engineer-logging.service (or another rpi-engineer-* service) shows:

python: can't open file '/opt/rpi-engineer/services/logging_service/manager.py': [Errno 2] No such file or directory

Cause: Application files under /opt/rpi-engineer/services/ are missing or incomplete (e.g. install was interrupted before deploy, or the install was from a clone that did not include the full tree).

Resolution:

  1. Re-run the installer on the device: sudo /opt/rpi-engineer/bin/install.sh, choose Upgrade and use existing configuration. When run from /opt/rpi-engineer, the installer clones the repo and deploys web, services, bin, lib (requires network).
  2. Or from a machine with the full repo, copy the missing folders: rsync -av ./services/ user@192.168.50.1:/opt/rpi-engineer/services/ (and similarly for web, bin if needed).
  3. Then restart the failing service: sudo systemctl restart rpi-engineer-logging (or the service named in the error).

Interrupted installation: repair / continue

Symptom: The installer was stopped partway through (power loss, Ctrl+C, or a step failed and you fixed the cause).

What the installer does: It records progress in /tmp/rpi-engineer-install.progress. If you run the installer again and that file is present, you will see:

Interrupted installation detected (progress file present).
  1) Continue / Repair (resume from where it stopped)
  2) Start over (discard progress and run a new install)

Resolution:

  • Choose 1) Continue / Repair to resume. The script reuses your previous choices (from /etc/rpi-engineer/install.conf), skips steps already completed, and continues from the next step. You will be asked for the WiFi hotspot password again if the hotspot step had not completed.
  • Choose 2) Start over to remove the progress file and run a full new installation (you will go through the wizard again).

On a successful completion, the progress file is removed automatically.
