Network issues

Diagnose interface connectivity, routing, and hotspot availability.

Interface down

Symptom: Interface shows down in Advanced → Network.

Common causes: Cable disconnected or switch port disabled.

Resolution: Reseat cables and confirm link lights.

No WAN connectivity

Symptom: WAN status is disconnected.

Common causes: DHCP failure or wrong static settings.

Resolution: Reapply interface settings and verify gateway.

Hotspot unavailable

Symptom: WiFi hotspot SSID not visible.

Common causes: Hostapd not running or WiFi disabled.

Resolution: Reboot the device and retry after two minutes.

WiFi client overwrites hotspot after reboot

Symptom: After reboot, wlan0 connects to a saved WiFi network (client mode) instead of acting as the RPi Engineer hotspot (192.168.50.1).

Cause: Ubuntu (NetworkManager) or Raspberry Pi OS (dhcpcd / wpa_supplicant) manages wlan0 for client WiFi and overrides the hotspot configuration.

What the installer does: The installer configures hotspot priority so the hotspot wins:

  • NetworkManager (Ubuntu / RPi OS with NM): Adds /etc/NetworkManager/conf.d/rpi-engineer-wlan0-unmanaged.conf so wlan0 is unmanaged (not used as a WiFi client).
  • dhcpcd (Raspberry Pi OS): Appends denyinterfaces wlan0 to /etc/dhcpcd.conf so dhcpcd does not manage wlan0.
  • Boot order: The rpi-engineer-wlan0 service runs before hostapd: it stops wpa_supplicant on wlan0, brings the interface up, and assigns 192.168.50.1. Then hostapd starts and runs the hotspot.

If you installed before this change, re-run the installer (upgrade) or manually add the NetworkManager/dhcpcd config and enable rpi-engineer-wlan0.service.

Hotspot password not working after reboot

Symptom: The WiFi password you set during install (or in Advanced → Network → Hotspot) does not work after rebooting.

Cause: The hotspot SSID and password must be reapplied to /etc/hostapd/hostapd.conf at every boot; otherwise another service or package can overwrite that file.

What the installer does: Credentials are stored in /etc/rpi-engineer/hotspot.secret (mode 600). The rpi-engineer-wlan0 service runs before hostapd and, if this file exists, writes the stored SSID and password into /etc/hostapd/hostapd.conf. So the password you set at install or via the web UI is applied on every boot.

If the password still fails after a reboot, ensure rpi-engineer-wlan0.service is enabled and that /etc/rpi-engineer/hotspot.secret exists and contains the SSID on the first line and the password on the second line. Reconfiguring the hotspot from Advanced → Network → Hotspot will recreate this file.
