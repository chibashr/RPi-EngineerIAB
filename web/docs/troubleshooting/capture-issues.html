Capture issues

Troubleshoot packet capture failures and performance concerns.

Capture fails to start

Symptom: Capture does not start or ends immediately.

Common causes: Interface not available or missing permissions.

Resolution: Select another interface and retry.

Live view: Permission denied (dumpcap)

Symptom: Live view shows an error like Couldn't run dumpcap in child process: Permission denied or 0 packets captured.

Cause: Capturing raw packets on an interface requires elevated privileges. tshark uses dumpcap, which needs the cap_net_raw (and usually cap_net_admin) capability, or the process must run as root.

Resolution:

  1. If you installed or upgraded recently: The installer and apply-web-permissions.sh set dumpcap capabilities automatically. Run sudo /opt/rpi-engineer/bin/apply-web-permissions.sh to re-apply (e.g. after a wireshark/tshark update that replaced dumpcap). Then sudo systemctl restart rpi-engineer-api.
  2. Manual (capabilities): Give dumpcap permission to capture without full root: sudo setcap cap_net_raw,cap_net_admin=eip $(which dumpcap). Then restart the API: sudo systemctl restart rpi-engineer-api.
  3. Alternative: Run the API service as root (not recommended for production).

After applying capabilities or running as root, start a new capture and open the live view again.

Capture file too large

Symptom: Capture fills storage quickly.

Common causes: High traffic or no filter.

Resolution: Add a BPF filter or shorten the duration.

Live view not updating

Symptom: Live view shows no packets.

Common causes: Filter too restrictive or no traffic.

Resolution: Clear filters and generate test traffic.
