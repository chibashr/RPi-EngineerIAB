Capture issues

Troubleshoot packet capture failures and performance concerns.

Capture fails to start

Symptom: Capture does not start or ends immediately.

Common causes: Interface not available or missing permissions.

Resolution: Select another interface and retry.

Capture or live view: Permission denied

Symptom: Capture does not start, or live view shows Permission denied or 0 packets captured.

Cause: Capturing raw packets requires elevated privileges. The API runs as rpi-engineer and uses tcpdump (and optionally tshark/dumpcap) which need cap_net_raw and cap_net_admin, or the process must run as root.

Resolution:

  1. If you installed or upgraded recently: The installer and apply-web-permissions.sh set tcpdump capabilities automatically. Run sudo /opt/rpi-engineer/bin/apply-web-permissions.sh to re-apply (e.g. after a tcpdump package update). Then sudo systemctl restart rpi-engineer-api.
  2. Manual (capabilities): Give tcpdump permission to capture without root: sudo setcap cap_net_raw,cap_net_admin=eip /usr/sbin/tcpdump. Verify with getcap /usr/sbin/tcpdump. Then restart the API: sudo systemctl restart rpi-engineer-api.
  3. Verify as service user: sudo -u rpi-engineer tcpdump -i any -c 5 — if that works, the web API will too.
  4. Alternative: Run the API service as root (not recommended for production).

Captures are stored in /var/lib/rpi-engineer/captures. Ensure that directory exists and is owned by rpi-engineer.

Capture file too large

Symptom: Capture fills storage quickly.

Common causes: High traffic or no filter.

Resolution: Add a BPF filter or shorten the duration.

Live view not updating

Symptom: Live view shows no packets.

Common causes: Filter too restrictive or no traffic.

Resolution: Clear filters and generate test traffic.
