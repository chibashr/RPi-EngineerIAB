Serial issues

Resolve device detection and Serial console session problems.

Device not detected

Symptom: No devices listed in Advanced → Serial console.

Common causes: Adapter not connected or unsupported chipset.

Resolution: Reconnect the adapter and refresh the page.

Permission denied

Symptom: Cannot open device or session fails to start.

Common causes: The service user needs to be in dialout and/or plugdev to access serial ports (ttyUSB*, ttyACM*). On many systems, udev assigns USB serial devices to plugdev.

Resolution: The installer adds the service user to dialout and plugdev automatically. If you installed before this was added, or permissions were skipped: re-run the installer, or manually run sudo usermod -a -G dialout rpi-engineer and sudo usermod -a -G plugdev rpi-engineer, then sudo systemctl restart rpi-engineer-api. A reboot also applies new group membership.

No output (Tx > 0, Rx = 0)

Symptom: You can type and send commands, but no prompt or response appears from the device.

Common causes: Baud rate mismatch. Many devices use 9600 for console; others use 115200 or 38400.

Resolution: Click Configure on the device, set the baud rate to match the target (e.g. 9600, 115200), then disconnect and reconnect the session.

Garbled output

Symptom: Output is unreadable.

Common causes: Incorrect baud rate or parity.

Resolution: Update device settings to match the target device.

504 Gateway Timeout when connecting

Symptom: Click Connect and the request times out with 504 (Gateway Time-out).

Common causes: Nginx proxy uses a 60-second default timeout. Slow device scans or a busy system can exceed this.

Resolution: Run sudo /opt/rpi-engineer/bin/apply-web-permissions.sh to apply the updated nginx config (120-second timeout for API). Then sudo systemctl reload nginx.

WebSocket "Invalid frame header" or connection fails

Symptom: Serial console shows disconnected and the browser console reports WebSocket connection failed: Invalid frame header.

Common causes: Nginx proxy misconfigured or API service not running.

Resolution:

  1. Restart the API: sudo systemctl restart rpi-engineer-api.
  2. If behind nginx, ensure /ws/ has proxy_http_version 1.1, Upgrade, and Connection "upgrade" headers. Run sudo /opt/rpi-engineer/bin/apply-web-permissions.sh to re-apply the nginx config.
